# Frontend pages

This inventory covers the 39 page routes defined in `frontend/app`. Routes in square brackets are dynamic; one page template serves multiple units, lessons, contests, assignments, or algorithms.

| Route | Page | What it offers |
| --- | --- | --- |
| `/` | Landing page | Introduces QuantumLoop with animated quantum visuals, a nine-step learning-loop overview, prediction and AI-tutor previews, and a browser-local demo login/sign-up card. The footer call to action opens signup. |
| `/login` | Demo login | Creates a browser-local demo session from an email and password entry, with validation and a return to the intended page. No server authentication occurs. |
| `/signup` | Demo signup | Collects a name, email and password to start a local demo session. No server account is created. |
| `/forgot-password` | Account recovery request | Validates an email and explains that recovery email delivery needs an account service. |
| `/reset-password` | Reset link state | Shows missing, expired, invalid, checking, service-error, unavailable, valid-form, and success states. Demo tokens remain unavailable; expired/invalid screens are explicitly labeled previews. |
| `/settings` | Demo profile settings | Saves display name, learning focus, pace, and reduced-motion preference per local demo profile; can reset that profile’s lessons, assessments, activity, streaks, badges, and other learning progress. |
| `/home` | Learner dashboard | Recommends the first or resumed lesson, unit quiz, or challenge retry using the current learner’s progress and recent mistakes. Shows lesson completion, XP, recent activity, algorithm-stage status, a once-daily graded question, local simulation status, clearly labeled sample faculty guidance, and pending assigned work. |
| `/curriculum` | Curriculum map | Shows learner XP, level, and streak alongside nine sequential course units, completion counts, estimated duration, and XP. Offers a learner-specific start/resume link, practice review, and assigned work. Content is marked pending faculty review. |
| `/curriculum/[unitId]` | Unit overview | Shows level, duration, description, badge, available XP, resume/next lesson action, ordered lessons, quiz, and related published assignments. Units 4–7 link to their associated algorithm workbenches, including explicit unavailable states. Unit IDs are `u1` through `u9`. |
| `/assignments` | Learner assignment inbox | Lists published circuit-study assignments targeted to the signed-in demo profile, with due date, unit, quiz size, and submission status. |
| `/assignments/[id]` | Learner assignment | Shows the circuit diagram and gate sequence, study instructions, multiple-choice quiz, written response, optional code editor for manual review, draft save, submission, scored quiz feedback, attempts, and instructor feedback. Submissions also enter shared assessment history. |
| `/curriculum/[unitId]/[lessonId]` | Lesson | Uses the shared app shell and breadcrumbs, displays lesson text and interactive checkpoints with answer explanations, and provides previous/next lesson navigation. Hardware unit 9 lessons open relevant Builder Studio presets with a return link. Completion awards XP once and updates the learner's resume position. Unknown IDs use the shared not-found page. |
| `/curriculum/[unitId]/quiz` | Unit quiz | Presents unit-specific multiple-choice questions with required-answer validation, per-answer feedback, a 70% pass mark, results, and retry. Saves best score and attempt history; awards quiz XP once on first pass. |
| `/curriculum/practice` | Practice arena | Lets users choose circuit building, optimization, debugging, measurement, or quantum theory, then answer relevant track-filtered questions with immediate explanations. Links into simulator-graded circuit challenges. |
| `/contests/practice` | Contest practice | Reuses the same practice arena as `/curriculum/practice`. |
| `/challenges` | Challenge catalog | Lists local circuit challenges and a clearly marked code practice entry with topic, difficulty, completion status, and type filters. Cards show target behavior, attempt count, best score, and a direct solve/retry action. Attempts are stored in the browser-local learner progress profile. |
| `/challenges/code-practice` | Code practice | Lets a learner draft a Bell-pair program and request remote grading through the typed adapter. The demo reports that grading is unavailable and does not execute code; the screen supports pending and service-error states. |
| `/challenges/[id]` | Circuit challenge workbench | Shows challenge prompt, target distribution, constraints, a starter circuit, gate palette, removable gates, output preview, hints, submission, and an action to open the circuit in Studio. The supported circuits run on the local simulator. |
| `/challenges/[id]/attempts/[attemptId]` | Challenge submission review | Shows submitted circuit snapshot, score, pass state, per-check feedback, and simulated measurement distribution; supports retry and opening the saved snapshot in Studio. |
| `/lab/[algorithm]` | Algorithm lab | Beginner, Deutsch–Jozsa, and Grover tracks use the nine-stage Learn → Predict → Build → Run → Observe → Explain → Debug → Challenge → Master flow, the local statevector simulator, and workbench results. QAOA opens a three-vertex Max-Cut parameter workbench with γ/β/depth controls, expected-cut results, and evaluation history. VQE opens a two-qubit toy-Hamiltonian workbench with ansatz parameters, statevector energy results, and evaluation history. QAOA/VQE evaluations are manual local parameter trials, not optimizer-service runs; VQE is explicitly not a chemistry result. QFT, Shor, and QEC show an unavailable-track recovery screen. The route accepts `grover` as an alias for `grovers`; unknown names also get a recovery page. |
| `/studio` | Circuit Studio | A free-form circuit workbench with drag-and-drop gates, templates and saved circuits, visual/code/split views, gate inspection, a step scrubber, simulation results, a tutor drawer, undo/redo, sharing, and Qiskit/QASM/PNG/JSON exports. Circuit data is stored in the browser. |
| `/hardware` | Hardware Studio overview | Explains dilution-refrigerator wiring and thermal constraints. Links to the component catalog, builder, and system checks, with counts of stages, components, line types, and validation rules. |
| `/hardware/catalog` | Component catalog | Browsable, category-filtered hardware components with descriptions, line compatibility, and key specs. A 3D preview loads when requested, keeping only one WebGL renderer active. A second tab shows a stage-compatibility matrix. |
| `/hardware/studio` | Hardware builder | Lets users place components on temperature stages and connect compatible ports using selectable XY, flux, readout, or DC signals. Diagram, 3D, and keyboard-accessible list views share the design and selection; the list includes placement and routing controls. Includes a component palette, inspector, current-design validation and thermal diagnostics, presets, and browser-local save/load. Hardware lessons open a preset and retain a return link; the 3D view offers a diagram fallback. |
| `/hardware/checks` | System checks | Lists validation rules with severity and suggested fixes, a cooling-power table for each stage, and diagnostics for the current hardware design. |
| `/contests` | Contest listing | Shows labeled sample contests, live/upcoming/ended filters, practice links, and the current browser-local learner's XP, entry and badge counts. |
| `/contests/[id]` | Contest detail | Shows the brief, scoring rules, sample rankings and contest-specific discussion. The supported Bell-pair demo accepts an entry, links to the shared circuit challenge, and shows the learner's saved submissions and reviews. Unsupported grading is explained; unknown IDs get recovery UI. |
| `/leaderboard` | Leaderboard | Filters one labeled sample ranking dataset by global, contest or learning module scope and by week/all-time period. Adds a separately labeled browser-local learner row when there is activity, plus a sample badge guide. |
| `/discussions` | Discussions | Lists sample and browser-local threads with working Top/New/Most Replies sorting, persisted voting and a new-thread dialog. Contest threads appear in their selected contest. |
| `/discussions/[threadId]` | Thread detail | Shows the post, available local replies, labeled sample reply counts, persisted voting and a reply composer; unknown IDs get recovery UI. |
| `/me` | Quantum Passport | Shows the current learner’s browser-local name, level and XP, activity streak, 52-week heatmap, earned and locked badges, recorded quiz/challenge scores by concept, lab prediction calibration, and a timeline of lessons, assessments, and local simulations. Fresh learners see empty states. The Bloch sphere remains a separately labeled interactive preview. |
| `/instructor` | Instructor dashboard | Shows browser-local learner counts, attention flags, missed questions, recent assessment activity, and assignment pulse from shared profile and coursework records. Links to assessments, curriculum review, preferences, contests and discussions. Empty cohorts get a useful starting state. |
| `/instructor/students` | Learner roster | Searchable list of local learner profiles and submissions with concept/progress filters, attention reasons, assessment counts and links to learner details. |
| `/instructor/students/[studentId]` | Learner detail | Shows lesson and lab progress, concept scores, unified assessment history, hint use, assignment responses, and a suggested review link based on missed questions. Unknown learner IDs get recovery UI. |
| `/instructor/misconceptions` | Question patterns | Aggregates missed quiz and assignment questions by affected learners and attempt count, with links to the related lesson or challenge and learner profiles. Does not infer beliefs from incorrect answers. |
| `/instructor/curriculum` | Curriculum review | Browses all nine units and lesson content, labels faculty-review status, previews learner-facing lessons and unit quizzes, and links to assessment authoring. |
| `/instructor/assessments` | Reusable assessment editor | Saves versioned quiz, code-response and circuit-debug templates with a circuit snapshot, questions, explanations, written prompt and optional starter code. Previews the learner view and loads a copy into assignment authoring. Templates live in this browser; the service contract supports future API persistence. |
| `/instructor/assignments` | Assignment authoring | Lets an instructor demo user choose a curriculum unit and built-in, saved, current Studio, or reusable assessment circuit; write instructions; add/edit multiple quiz questions and explanations; preview the learner view; target all local learners or one email; save drafts, publish, or create a new version. Code assignments collect a text response for manual review. |
| `/instructor/assignments/[id]` | Assignment review | Shows the published or draft task, circuit and answer key, submitted learner quiz, written and code responses, and a manual feedback form. Feedback updates the learner's shared assessment record. |

## Current implementation notes

- Curriculum lesson copy and checkpoints are scaffolded and explicitly marked for faculty review. Units `u4`–`u8` currently use a single generated overview lesson each; hardware unit `u9` has three distinct lessons and preset exercises.
- Shared app pages use a lightweight visible background, and the full navigation collapses below desktop width. Hardware state and the command palette load only when their route or shortcut is used; the catalog and builder load 3D renderers only when requested. The browser suite covers all 39 route templates, key journeys, and representative phone, tablet, and desktop widths. The development server compiles routes on demand; use a production build when judging page latency.
- Contest participant counts, ranking examples and seed discussion counts are explicitly labeled sample data. Only the Bell-pair contest has local graded entry; noise grading and other unsupported contests need backend services. The dashboard’s faculty note is labeled sample content. Instructor analytics and community activity cover only records created in the same browser.
- Learner progress (including quiz, circuit challenge, lab challenge and assignment attempts), coursework, community threads/replies/votes/entries, Circuit Studio state, Hardware Studio designs, and demo session information use browser-local persistence. Instructor publishing reaches only demo learner profiles in the same browser; production roles, delivery, storage, and trusted grading require backend services. Circuit challenge grading covers the listed supported simulator problems; remote code grading has a typed adapter and a pending/error UI but needs a backend before it can return a real result. The Circuit Studio tutor is a deterministic circuit-aware mock.
