# Backend provider decisions (B01)

These are implementation choices, not evidence that paid accounts, credentials, or production deployments have been tested. Keep secrets server-side and complete the credentialed smoke gates in B23.

| Capability | Selected provider | Configuration and deployment boundary | Remaining proof |
| --- | --- | --- | --- |
| Identity | Supabase Auth | Verify asymmetric JWTs against the project JWKS; set `QL_AUTH_ISSUER` to `https://<project>.supabase.co/auth/v1` and `QL_AUTH_AUDIENCE=authenticated`. The frontend owns provider signup, refresh, recovery, and bearer-token acquisition. | Test real signup, refresh, key rotation, and logout. |
| SQL | Supabase PostgreSQL | `QL_DATABASE_URL` is a `postgresql+psycopg://` URL. Put API, workers, and database in the closest available regions. Use direct connectivity where supported; use the session pooler for IPv4-only long-lived processes. Run migrations through a separate direct connection when possible. Set a total process-wide connection budget. | Provision project and exercise migrations, concurrency, backup/restore. |
| Object storage | Supabase Storage S3 endpoint | Server-only S3 credentials, project endpoint, bucket, and key prefix. Store ownership/checksums/object keys in PostgreSQL. Export downloads use short-lived signed URLs; browser never receives S3 secret keys. | Provision bucket, verify upload/download/deletion and access control. |
| API and workers | Render web service plus background workers | `render.yaml` builds the checked-in Dockerfiles from a selected commit for separate API, Aer worker, and dispatcher services; the API pre-deploy step runs Alembic once. Auto deploys are disabled for controlled promotion. The manual GHCR workflow publishes commit-tagged images separately. | Apply the Blueprint, run migrations, smoke test, measure latency and worker capacity. |
| Broker and cache | Two separate paid Render Key Value instances | Broker: durable persistence, `noeviction`, TLS (`rediss://`) when crossing private-network boundaries, alert on memory/connection use. Cache: independent instance with an eviction policy. Celery broker and Socket.IO manager use persistent Redis connections; pub/sub belongs on the cache/realtime instance, never the broker. Business results remain in PostgreSQL. | Check purchased plan limits, persistent-connection count, TLS URLs, pub/sub between two live Socket.IO instances, and task redelivery under restart. Documentation review alone does not close B01's live Redis verification item. |
| Code grading | Self-hosted Piston on an isolated host | Piston's Docker executor needs privileged operation; keep it off the Render API and ordinary Celery hosts. Reach it only through authenticated private networking from a grading worker. | Threat review, provision isolated host, enforce CPU/memory/network/time limits and run hostile-code tests. |
| AI tutor | OpenAI API, `gpt-5.4-mini` initial model | One server-side OpenAI-compatible `chat.completions` adapter; configure API key, base URL, model, timeout, token/cost budgets, and fallback behavior. Pin a model snapshot only after tutor evaluations justify it. | Evaluate pedagogy, latency, cost, streaming, and safety in B13. |
| Hosted quantum | qBraid API v2 | Server-only `QL_QBRAID_API_KEY`, default API base `https://api-v2.qbraid.com/api/v1`, and an explicit allowlist of device QRNs. Require a per-run shot/cost limit and cost preview before paid hardware submission. Hosted execution and local qBraid transpilation are separate adapters. | Credentialed capability/device discovery, quota/cost checks, submission/polling/cancellation tests in B08. |

The URLs and provider features above were checked against the providers' documentation on 2026-09-28. Plans, quotas, and prices can change; verify the account-specific values before production deployment.
